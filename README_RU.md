# HTML → FIG Studio

Веб-приложение переносит страницы и состояния интерфейса в один файл `.fig`. Браузерный помощник последовательно открывает ссылки, раскрывает меню и панели, переключает вкладки и нажимает другие видимые элементы, доступные для безопасного просмотра. Для каждого найденного состояния Chromium снимает страницу и измеряет её элементы. В Figma у каждого состояния свой фрейм с редактируемыми текстами, формами и группами. Рядом сохраняется фрейм с исходным снимком Chromium для сравнения.

## Локальный запуск

Установите [Node.js LTS](https://nodejs.org/) версии 20 или новее. Из каталога проекта выполните:

```sh
npm ci
npx playwright install chromium
npm start
```

На Linux при отсутствии системных библиотек используйте `npx playwright install --with-deps chromium`. На Windows можно запустить `start_windows.bat` из распакованной папки, на macOS и Linux — `sh start_mac_linux.sh`. При первом запуске нужны доступ к npm и загрузка браузера Playwright.

1. Откройте приложение по адресу `http://127.0.0.1:4318`.
2. Введите URL или вставьте свой HTML. Для первого прогона нажмите **Загрузить демо**.
3. Включите **Открывать ссылки и нажимать элементы интерфейса**. Выберите ширину экрана, предел числа состояний и паузу после действий. Нажмите **Собрать .fig**.
4. Просмотрите найденные состояния и скачайте `.fig`. В браузере файлов Figma выберите **Import** и укажите скачанный файл.

Для уже установленного Chromium можно задать путь к программе через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Порт по умолчанию `4318`. Его можно изменить через `PORT`.

## GitHub Pages

[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) размещает статический интерфейс из папки `public/`. Chromium и сборка `.fig` работают в отдельном Node.js-процессе. Это даёт интерфейсу Pages возможность конвертировать страницы с собственными стилями и сценариями через один и тот же API.

В репозитории включите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` выполняет тесты и публикует интерфейс после успешной проверки ветки `main`. Для проекта `Sweaty6/HTML_to_Figma` стандартный адрес будет `https://sweaty6.github.io/HTML_to_Figma/`.

### Pages с локальным обработчиком

Укажите в CORS точный origin страницы GitHub Pages, без имени репозитория и без завершающей косой черты:

```sh
H2F_ALLOWED_ORIGIN=https://sweaty6.github.io npm start
```

В PowerShell перед запуском используйте `$env:H2F_ALLOWED_ORIGIN = 'https://sweaty6.github.io'`. На странице GitHub Pages откройте **Сервер обработки**, укажите `http://127.0.0.1:4318` и нажмите **Проверить подключение**. Если браузер запросит доступ к локальной сети, разрешите его для этого подключения. Адрес должен быть доступен с компьютера, на котором открыт браузер.

### Pages с удалённым обработчиком

Разверните тот же Node.js-процесс на сервере с Chromium. Оставьте Node.js на loopback, поставьте перед ним reverse proxy с TLS и используйте HTTPS-адрес API в интерфейсе Pages. Укажите точный origin в `H2F_ALLOWED_ORIGIN` и задайте приватный `H2F_TOKEN` длиной от 32 символов через окружение сервера. Введите этот же токен в интерфейсе. Храните токен только у пользователей, которым разрешена конвертация. Для привязки к другому интерфейсу используется `H2F_HOST`, по умолчанию `127.0.0.1`.

Запускайте Chromium под отдельным непривилегированным пользователем в изолированной среде. Обработчику нужны DNS и прямые исходящие соединения с общедоступными сайтами по HTTP 80 и HTTPS 443. Для входящих запросов настройте ограничение частоты и размера. Используйте один экземпляр обработчика на один адрес API, поскольку результаты хранятся в памяти процесса.

### Опциональный ИИ

Базовый обход работает по правилам и доступен сразу после запуска. Для приоритизации действий моделью задайте `H2F_AI_API_KEY` и `H2F_AI_MODEL` на сервере. `H2F_AI_ENDPOINT` позволяет указать HTTPS-адрес совместимого сервиса Chat Completions. После проверки подключения пользователь может включить ИИ в интерфейсе. Модель получает подписи, типы и состояния элементов управления. При недоступности модели используется обычный порядок обхода.

## Как работает обход

- Помощник выбирает видимые ссылки и элементы управления по DOM, роли и подписи. Он исследует разные последовательности действий и сохраняет отличающиеся состояния, включая состояния на том же URL. Формы и загрузки исключены из обхода. Действия, похожие по подписи на оплату или изменение данных, отфильтровываются.
- После действия помощник ждёт выбранную паузу и даёт конечным анимациям время завершиться. Прокрутка загружает отложенные изображения. Снимок Chromium и координаты DOM относятся к одному состоянию.
- Отдельные страницы по URL открываются в пределах исходного origin. Режим HTML обходит состояния внутри переданного документа. Обход ограничен бюджетом состояний, числа действий, глубины и времени. Переходы в новых вкладках, сторонние iframe и действия, требующие авторизации, могут остаться за пределами результата.
- Снимок передаёт пиксели Chromium в момент захвата. Редактируемые слои восстанавливаются по геометрии и вычисленным стилям. Для сложных эффектов и части медиа используются растровые слои. Шрифты, метрики текста, наложения и эффекты могут отличаться в Figma. Снимки длинных страниц ограничены по размерам.

## Проверка

```sh
npm test
```

Тесты используют Chromium и проверяют работу захвата и структуру бинарного архива. Файлы демо дополнительно читались независимым декодером Figmatik. Совместимость импорта проверьте в Figma на том же демо. Откройте несколько фреймов, проверьте редактируемость текста и сравните их со снимками рядом. Затем повторите со страницей из проекта «Зерон», доступной по URL. [Figmatik (MIT)](https://github.com/KonstantinBelan/figmatik)
